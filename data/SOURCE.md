# BookMatch catalog source

The bundled catalog contains 20,000 Open Library works selected from the 2026-08-31 monthly data dumps. The ranking counts entries marked `Already Read` for each work in Open Library's public reading-log dump, then sorts by count (ties by work key). These are reading-log entries, not verified unique readers, sales figures, or a worldwide popularity ranking. Works without a usable title and author in the same snapshot are skipped; the next ranked complete works fill the 20,000 places.

For each selected work, BookMatch bundles only its Open Library work key, title, author name, up to 24 subject tags, first publication year when available, public work URL, aggregate read count, and rank. A separate compact index maps 19,351 of these works to public cover IDs. It does not bundle reader records, personal libraries, descriptions, cover artwork, or the bulk source dumps. Subject tags are catalog metadata and should not be treated as content warnings.

In this snapshot, 17,726 selected works have a description in the source work dump; 18,857 have subject tags; 14,059 have tags that support one of BookMatch's broad genre labels; and 19,351 have a cover ID. BookMatch does not store edition data, page counts, or ISBNs. These are availability counts, not a guarantee that every description or cover is suitable for redistribution or accurately represents every edition.

Sources: [Open Library data dumps](https://openlibrary.org/developers/dumps), [bulk data guidance](https://openlibrary.org/data), and [Open Library licensing information](https://openlibrary.org/developers/licensing). The catalog is public-source metadata with attribution to Open Library; the BookMatch application code remains unlicensed at the owner's request.

To reproduce the catalog, download the matching `ol_dump_reading-log_2026-08-31.txt.gz`, `ol_dump_works_2026-08-31.txt.gz`, and `ol_dump_authors_2026-08-31.txt.gz` files to the ignored `.catalog-source/` directory as `reading-log.txt.gz`, `works.txt.gz`, and `authors.txt.gz`. Then run:

```sh
.venv/bin/python -m scripts.build_catalog --snapshot 2026-08-31
```

This writes the compact `data/catalog.json`. The download directory is ignored by Git. Catalog search and filters use only local metadata; visible cover cards may fetch their images as described below. BookMatch suggests broad genres only from explicit public subject tags. **Look up more details** in Add a book uses Open Library's [Works API](https://openlibrary.org/dev/docs/api/books). Opening Details for a catalog book with a missing description also looks up that individual public work when no response is cached. Responses are cached locally, and only the public work ID is sent; typed search text and Goodreads data are never sent. Work lookups are limited to individual books, consistent with [Open Library's low-volume API guidance](https://openlibrary.org/developers/api).

Run `.venv/bin/python -m scripts.extract_catalog_covers` against the same local works dump to create `data/cover_ids.json`. The app fetches a [medium Open Library cover](https://openlibrary.org/dev/docs/api/covers) only when its card becomes visible and saves it in the private application data folder. At most two cover requests run at a time. Open Library asks developers not to crawl its cover service, so the bulk download instead retrieves selected public image members from [Archive.org's medium cover archives](https://archive.org/details/m_covers_0000). Run `.venv/bin/python -m scripts.download_covers` to populate the same private cache. The script is resumable, uses at most two concurrent requests, and stops below 2.8 GB of cached image payload. It skips archive groups that have no public image files. Some cover IDs are missing from historical archives; the app can load those on demand while browsing. Cover requests contain only public cover IDs, not personal library information or search text. The private image cache is ignored by Git and is not bundled in the app.
